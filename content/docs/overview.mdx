# Overview

Wheel is an opinionated framework for building local-first web apps with agents.

It ships the state layer, the sync engine, the component bindings, the debug surfaces, and the lint rules that hold them together.

The bet behind Wheel: **agents write good code when the framework makes bad code impossible.** Every piece of state has a name, an owner, and a record of what wrote it. Every component declares exactly what it reads. Every rule that matters is enforced by a machine, not a code review.

Here is the whole model in one file — a service owns state, and nothing else may write it:

```ts
// Excerpt: packages/docs/examples/getting-started/todo-service.ts
export class TodoService extends SyncService {
  readonly list = this.liveQuery(todoList, {});
  readonly remaining = this.computed(() => this.list.rows.filter((todo) => !todo.done).length);
  readonly add = (text: string) => this.mutate(addTodo, { text });
}
```

A component reads that service through one `connect()` call, and through nothing else. [Getting Started](#/getting-started) runs it.

## Design principles

Four properties drive every design decision:

1. **Consistency.** One way to do each thing, applied everywhere. The patterns are simple, composable, and repeated across every app in this repo.
1. **Modularity.** Components are self-sufficient units: each declares its own data needs and plugs into the state system wherever it is mounted. No prop drilling, no parents doing their children's jobs.
1. **Debuggability.** Every component can answer "what state do you have and where did it come from?" precisely — which service owns it, which mutation wrote it, and where it was loaded from.
1. **Testability.** Because components declare their needs up-front, each one builds and tests in isolation. Every service swaps for a fake with one line. The whole sync engine runs in-process with a fixed clock and seeded randomness, so tests reproduce byte-for-byte.
