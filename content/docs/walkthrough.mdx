# Walkthrough

Build a synced todo app end to end: the data declaration, the server, the client, the service, the component, and the dev proxy.

Every source block comes from a real file under `packages/docs/examples/getting-started`. `bun run typecheck` compiles those files, and `bun run lint` applies the same application rules a consumer gets.

Install Wheel with `bun add wheel@npm:@cannoneyed/wheel@0.1.0 solid-js`. The repository examples resolve `wheel` from the workspace. [Getting Started](#/getting-started) covers both workflows.

Everything from Wheel comes through a documented [public subpath](#/import-map). This example uses Bun's in-process SQLite driver, a persistent `todos.db` file, and Vite's same-origin development proxy.

## 3. Boot the authenticated server (`server.ts`)

One `SyncServer` owns one workspace and one database. See [Server and backends](#/server) for SQLite and ownership. `authenticateSyncSocket` verifies the WebSocket upgrade. Message bodies never choose their actor or workspace. This example accepts two demo-only query values. A real application verifies a cookie or a one-use ticket.

The server handles both shutdown signals and awaits `syncServer.close()`, which closes its owned backend.

## 4. Keep storage and wire identities separate (`client.ts`)

The IndexedDB scope is stable in `localStorage`, so cached rows and the durable outbox survive reloads. The WebSocket id is fresh for each page load. The server allows one live socket per id. Do not put the id in `sessionStorage`. Browsers can copy it into duplicated tabs, which makes the sockets replace each other.

Using one new random id for both jobs would abandon the previous cache after each reload. The split preserves local-first continuity: the cache and outbox outlive the page, the wire id does not.

The checked-in `row-schema.generated.ts` comes from the same sync declarations and server bindings
that boot the server. Run `bun run row-schema:docs` after changing either input. CI runs the matching
check command and rejects a stale file. The generated fingerprint scopes cached snapshots and
cross-checks the browser and server during the WebSocket handshake. It does not replace the ordered
application version.

<Aside kind="note">
  <strong>Can't wrap your root?</strong> Docs embeds and sandboxes render into a page that
  already owns the tree. For those, mount <code>&lt;WheelProvider client&gt;</code> yourself and

</Aside>
