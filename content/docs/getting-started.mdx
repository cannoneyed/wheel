# Getting Started

Start a reference app on your machine, then write the three files every feature needs: a service, a connected component, and a root.

## Install Wheel

```sh
bun add wheel@npm:@cannoneyed/wheel@0.2.0 solid-js
```

`wheel` is the local npm alias for `@cannoneyed/wheel`. Keep imports such as `wheel/core` and `wheel/sync` unchanged.

## Run a repository reference app

Clone this repository when you want to run its reference applications.

1. Install dependencies: `bun install`
2. Start the demo sync server: `bun run demos:server`
3. Start the demo app: `bun run demos`
4. Open `http://localhost:4796` and add a todo.

Each app is two processes: a Vite dev server for the browser, and a Bun process for sync.

| App | Browser | Sync server | Opens on |
| --- | --- | --- | --- |
| Demos (`packages/demos`) | `bun run demos` | `bun run demos:server` | `http://localhost:4796` |
| Tracker (`packages/tracker`) | `bun run tracker` | `bun run tracker:server` | `http://localhost:4798` |
| Docs (this site) | `bun run docs` | — | `http://localhost:4780` |

Stop the sync server and keep adding todos. Writes queue in IndexedDB and replay when the server comes back. That is the local-first guarantee — [Live State](#/live-state) explains how it holds.

A service is a singleton class that owns shared state. `Service` (from `wheel/core`) holds local state; `SyncService` (from `wheel/sync`) adds server-synced state, where `liveQuery` subscribes to a query and `mutate` writes through it.

## 2. Connect a component

`connect(name, builder)` is the only way a component reads a service. The builder returns a `view()`: named reads and named actions. The component gets that view, never the service object.

<CodeExample example={todoListSource} />

Four rules the linter enforces here:

| Rule | What it requires |
| --- | --- |
| `single-connect` | One connection function per component, named `connect<Name>`, called first |
| `connect-only` | Services reached through `connect()` only — no context reads, no service hooks |
| `require-component-root` | `use:componentRoot` on the component's real DOM root |
| `require-use-signal` | `useSignal(initial, 'name')` for component-local state, not `createSignal` |

Component-local state stays in the component. The draft input above is local; the todo list is not.

## Development

### Use Wheel from a local checkout

Build Wheel, then install the local directory without changing the consumer manifest or lockfile:

```sh
bun run --cwd ../wheel-dev/packages/wheel build
bun add --no-save wheel@file:../wheel-dev/packages/wheel
```

Rebuild after each Wheel source change. Run the `bun add --no-save` command again to replace the prior local output.

Configure Vite before you start the app:

<CodeExample example={viteConfigSource} />

`resolve.dedupe` makes the app and Wheel use one `solid-js` runtime. Wheel throws during provider startup when the active Solid owner comes from a second runtime.

`wheelDevTools()` enables the debug panel and `window.__wheel` during `vite serve`. It keeps those surfaces off during `vite build`, preserves service names, and rejects a direct `file:` dependency when its source no longer matches the built package.
