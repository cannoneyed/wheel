# Component library

`wheel/components` provides accessible Solid component families. The default stylesheet applies the Mira zinc theme and remains opt-in.

[Browse the live components](https://wheel.dev/components/). Each family page includes an interactive preview, theme controls, and its deep import path.

## Setup

Import the stylesheet once at the application entry point:

```tsx
// Excerpt: Load the default theme and aggregate API.
import 'wheel/components/styles';

import { Button, Dialog } from 'wheel/components';
```

Import one family from its deep entry when a package boundary needs it:

```tsx
// Excerpt: Import one component family through its deep entry.
import { Dialog } from 'wheel/components/dialog';
```

The aggregate and deep entries expose the same component objects and public types.

## Button family

The Button family shares four variants and three dense sizes. `ButtonGroup` connects actions, while `ToggleGroup` owns selection.

| Component | Default | Use |
| --- | --- | --- |
| `Button` | `secondary`, `md` | Text actions, form actions, styled links, and async actions |
| `ButtonGroup` | `secondary`, `md`, horizontal | A compact set of connected actions with roving focus |
| `IconButton` | `secondary`, `md` | Compact actions with a required accessible label |
| `Toggle` | `ghost`, `md` | One pressed or unpressed tool |
| `ToggleGroup` | `single`, `secondary`, `md`, horizontal, `hug` | Single-select or multi-select pressed choices |

```tsx
// Intentionally unchecked: Fragment showing both Button family group forms.
import { Button, ButtonGroup, IconButton, Toggle, ToggleGroup } from 'wheel/components';

<ButtonGroup aria-label="Message actions" variant="primary" size="sm">
  <Button>Reply</Button>
  <IconButton label="More reply options" icon={<span aria-hidden="true">•••</span>} />
</ButtonGroup>

<ToggleGroup aria-label="Text alignment" defaultValue="left" layout="fill">
  <Toggle value="left" label="Left" />
  <Toggle value="center" label="Center" />
  <Toggle value="right" label="Right" />
</ToggleGroup>
```

Multi-part families use a namespace:

```tsx
// Intentionally unchecked: Complete multi-part composition example.
import { Dialog } from 'wheel/components';

export function DeleteDialog() {
  return (
    <Dialog.Root>
      <Dialog.Trigger>Delete project</Dialog.Trigger>
      <Dialog.Portal>
        <Dialog.Backdrop />
        <Dialog.Popup>
          <Dialog.Title>Delete project?</Dialog.Title>
          <Dialog.Description>This action cannot be reversed.</Dialog.Description>
          <Dialog.Close>Cancel</Dialog.Close>
        </Dialog.Popup>
      </Dialog.Portal>
    </Dialog.Root>
  );
}
```

## Default identities

Rendered parts keep a stable class and `data-slot` attribute. `Button` renders `wheel-Button` and `data-slot="button"`; `Dialog.Popup` renders `wheel-Dialog-Popup` and `data-slot="dialog-popup"`.

Your `class` prop is added to the default class:

```tsx
// Excerpt: Add an application class without replacing the Wheel class.
<Button class="billing-submit">Pay now</Button>
```

`Autocomplete` reuses the shared `Combobox` part implementations. Those shared parts keep their `wheel-Combobox-*` classes and autocomplete behavior.

## Theme tokens

[`packages/wheel/src/components/styles/tokens.css`](../../packages/wheel/src/components/styles/tokens.css) is the single source for Wheel component design constants.

`packages/wheel/src/styles/tokens.css` is a separate app-shell palette exported as `wheel/styles`. Component recipes do not read spacing, shape, color, or motion values from that file.

| Token group | Defines |
| --- | --- |
| Type | Font family, sizes, line heights, and tracking |
| Space and shape | Base spacing unit, radii, and hairline width |
| Motion | Instant, fade-out, state, layout, navigation, gesture, and continuous-loop durations; easing curves |
| Surfaces | Background, foreground, border, accent, validation, selection, backdrop, and shadow colors |
| Focus | Ring color, width, offset, and opacity |

Component recipes may define local geometry such as popup width. They read shared design values from `tokens.css` and do not declare private timing values.

Override semantic `--wheel-component-*` tokens on `:root`, a theme container, or one component instance after the default import:

```css
.brand-theme {
  --wheel-component-accent: oklch(0.55 0.22 264);
  --wheel-component-accent-fg: white;
  --wheel-component-radius-md: 0.25rem;
}
```

Light and dark values follow `color-scheme`. Set `data-theme="light"` or `data-theme="dark"` on a container to select one mode.

## Recipe overrides

Wheel puts its defaults in cascade layers. Unlayered application CSS declared after the import overrides a recipe without `!important`:

```css
.wheel-Button {
  min-height: 2.25rem;
  padding-inline: 1rem;
}

[data-slot='dialog-popup'] {
  width: min(32rem, calc(100vw - 2rem));
}
```

Use the class when the rule targets one component part. Use `data-slot` when the rule represents a shared application convention.
