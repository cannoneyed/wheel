# The framework for agents

Wheel is a batteries-included framework for building apps on [Durable Objects](https://www.cloudflare.com/products/durable-objects/) using agents.

- **Core primitives** [Solid.js](https://www.solidjs.com/), [signals](https://docs.solidjs.com/concepts/signals), [immutable state](https://github.com/immerjs/immer), and [state machines](https://github.com/statelyai/xstate).
- **Local-first sync engine** optimized for [Durable Objects](https://www.cloudflare.com/products/durable-objects/), backed by SQLite.
- **Strict conventions** for managing state and fighting complexity.
- **Agent debugging tools** expose application state and write history at runtime.
- **Batteries-included** with app-level functionality (e.g. routing, keyboard commands), building-blocks (e.g. context menus, command palette), layout, and a customizable component library.

<Section title="Reinventing the wheel">

Alan Kay coined the term "object-oriented" and then spent thirty years saying nobody understood him. His objects were supposed to be whole computers. Isolated, addressable, talking only by message. He called it _recursion on the notion of computer itself_ — computers all the way down.

This idea needed a computer per object, but it was never really practical - until now.

[**Durable Objects**](https://www.cloudflare.com/products/durable-objects/) make *computers* cheap and **agents** make *software* cheap.

Wheel is optimized for building these "object applications": a document, a spreadsheet, a canvas, or a single widget, each running on its own Durable Object with its own state.

Wheel is an opinionated framework for the agentic era - a world where every widget is a website.

</Section>

<Section title="Optimized for agents">

Most existing web frameworks were optimized for people, but Wheel is optimized for agents.

* One way to hold state (observable signals, managed by services).
* One way to change it (actions and mutations).
* One way for a component to read it (`connect()`).
* And one way for agents to access and understand everything about the application at runtime.

<Snippet of={ConnectSnippet} />

Components stay _modular_ and _composable_. You can move them between the application and isolated playgrounds without adapters.

Because every read is declared, the debugger can track where all state came from and how it's mutated. Data is immutable by default, and everything is visible to the developer and agent.

</Section>

<Section title="Local-first">

Every persisted write is a named mutation with an optimistic handler that runs against the local cache instantly. Go offline and writes queue in a durable outbox; come back and they replay in order.

<Snippet of={MutationSnippet} />

No CRDTs, no conflict-resolution puzzles — the server is the truth and the protocol is simple enough to read in an afternoon. The backend is optimized for [Durable Objects](https://www.cloudflare.com/products/durable-objects/) using SQLite.

<Section title="Rules, not conventions">

Every convention above ships as a lint rule, and every rule file opens with the story of the real bug it prevents. Zero errors is the only passing state. Escapes are in-file pragmas with a written reason — never a glob carve-out.

<Snippet of={LintSnippet} />

This is what makes the whole thing agent-proof: an agent can't drift out of the architecture, because the architecture is a build failure. When a new failure mode shows up, the fix is a new rule — the framework gets stricter as it ages, not looser.

</Section>
